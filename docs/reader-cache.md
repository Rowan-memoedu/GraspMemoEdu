# 阅读与状态缓存

Topic 首次进入仍经过服务器鉴权并加载当前可见步骤。侧栏、上一页、下一页的已学内容浏览直接使用内存中的步骤；本地选中位置不会写回学习记录，也不会被后台轮询重置。继续学习、判题、暂停、评分仍使用原有服务器事务、请求 ID 与版本冲突处理。

题组使用 `training/group?reader=1` 一次读取整组题面、指导、各题最近轮次状态和首批历史索引。未作答题目返回明确标记的 `preview`，不创建轮次、学习记录或 FSRS 卡。预览使用稳定的呈现 ID；首次提交、显示答案、加入错题本或启动外部练习前，才通过原有 `training/open` 创建对应轮次，选择题顺序保持一致。未开放的答案与解析不会进入预载包。

题组内切题直接读取内存，草稿沿用已有存储与管理员临时会话规则。更早的历史轮次仍按需读取并留存，历史索引按原分页策略扩展。题组每五秒后台校验一次；身份切换、登出或权限变化会清理当前阅读器，正文版本变化会替换整个题组。后台检查不会阻塞本地切换；写操作在途期间不允许旧检查结果覆盖新状态。

`access_revision`、`state_revision` 和 `content_revision` 是独立的显式协商参数。旧客户端不传参数，仍获得原 JSON。端点每次执行原鉴权和状态投影后才压缩返回值；不存在按摘要绕过权限读取正文的端点。

- `access_revision` 复用已验证的权限投影，避免每次附带完整 Topic 清单。
- `state_revision` 覆盖权限、内容、进度、依赖、暂停、判题、可用时间等完整投影。只有 `server_time` 单独随每次结果更新；相同状态返回摘要和时钟。
- `content_revision` 继续复用正文及公式，新增步骤只返回新文本块。

完整状态缓存仅存于当前页面内存，按身份、权限版本、API 地址和请求隔离，并设条目与容量上限；不会写入 IndexedDB。IndexedDB 只保存已有机制允许的正文。身份变化和异步响应之间保留代际隔离。缺失缓存只能重试 GET，任何不确定的 POST 均不自动重放。API 保持 `Cache-Control: no-store`，不交给共享 HTTP 缓存。

目录等较稳定数据在内存保留五分钟。页面导航使用已验证身份立即呈现，权限在后台校验；权限改变会重新读取当前路由。答疑编辑器按需加载。

验收使用 `scripts/performance_fixture.py` 和 `scripts/reader_cache_acceptance.mjs`。在独立数据目录启动真实 API，预载后人为给网络增加 1.2 秒延迟，验证 Topic 与整组题面 30 次切换的 P95 小于 100 毫秒、无逐次浏览请求、未提前创建轮次、实际作答判题及草稿保留。各注册学科共用同一机制。
