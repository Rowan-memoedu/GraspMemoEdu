# 题型与判题

来源适配支持 `interaction.version=2`：`choice` 可保留答案未确定状态；`composite` 由稳定 ID 的 controls 和有序 sections 组成。每个 section 保存 html、control_ids、complete，每个 control 为 select 或 text；select 保留原选项顺序。私有 answers 不进入公共投影。grading 为 exact、semantic 或 unavailable；整题按既有判题规则一次提交，最多 64 段、128 个控件、16384 字符。缺后续题面或答案时仅阅读，不把源抓取完成标记用作学员进度。

复合题的选择式填空同时提供正文空位下拉框和完整单选选项，两处同步同一答案；未选择时显示空白，下拉列表只包含原选项。只有英语篇章中的编号空位（完形、语法填空、七选五等）显示题号；其他学科的填写型或下拉型空位，以及没有来源编号的普通英语空位，均不自动增加编号。控件 ID、选项顺序以及 `{section, values}` 提交格式保持一致，已有草稿、分段门禁和只读历史沿用原规则。

英语完形、阅读复合题和七选五的正文与作答区左右并排，各自独立纵向滚动，仍按整题提交和调度。未填空的题号可用鼠标或键盘定位右侧相应选项组，并在区块内居中，不滚动正文或外层页面；首末题必要的居中留白仅影响右侧布局。题面位于 composite section 时同样置于左侧。加入错题本、内容反馈和答疑按钮置于整题右上角，正文和作答区均不重复。选项按右栏容器宽度和内容长度排成一、二或四列，随学习记录开关重排，桌面显示至少五组完形选项。手机仍保留两列并在各列内换行。

正文优先按显式 `data-control` 或 `{{blank:id}}` 绑定控件；旧英语篇章只有在编号空位与控件唯一对应时才增加原位输入。指导语中的题号范围、重复引用和普通数字保留；旧编号无法唯一对应时继续使用独立选项区。英语篇章配对题在右侧作答，填入的内容同步显示在左侧；其他配对题沿用原有布局。英语填空有内容后隐藏题号，只显示文本；下拉的选项字母只保留在菜单和选项区。可填写空位随词、词组或句子伸缩并自动换行，英文正文使用衬线字体，保留 Markdown 列表、缩进和制表符。

英语阅读理解不作为填空：编号设问与控件唯一对应时，将原段落或有序列表项移入右侧选项组，保留原文和内联格式；左侧不保留设问或跳转按钮。重复或无法唯一对应的数字保留原文。

选项颜色和逐题结果共用服务端反馈，各学科适用。`choice_feedback.items` 仅在答案侧投影，包含稳定 ID 和参考内容；已提交的精确作答复用服务端逐项判断补充 `correct`，展示答案和自主评分不虚构逐空结果，语义判题不按字符串推断。题号保持正文颜色，勾为绿色、叉为红色。英语完形及七选五参考答案在答对时仅显示绿色字母，答错时显示红色字母及选项全文；语法填空仅显示答案文本并按相同规则配色。

Example 与 Practice 共用可选 `interaction`（version 1）。不填时保留原问答题，继续交给已有 LLM 判题。`answer_type` 仍是原答案描述字段，不作为前端控件类型。

全站课程、复习、原子题、独立题库及历史页共用 `questionInput` 选择控件与 `choiceTypeField`，在习题编号或标题下显示“单选”或“多选”。鼠标、触摸、Tab 和空格操作保持，方向键不切换选项；Ctrl + Enter 提交。后端选项排序统一由 `present_choice` 处理，按作答标识保持稳定，`shuffle:false` 保持原顺序；选择题继续共用解析、隐藏答案与判分规则。

在作者 Markdown 的每题下，与 `Explanation` 并列增加一个 `Interaction` 节点；它只能包含一份 JSON 对象。该节点不显示在题干或解析里。原 `Explanation` 仍须保留，作为教学解析和旧判题参考。

```text
- 示例 Topic
  - Introduction
    - 学习说明。
  - Example 1
    - 太阳从 {{blank:east}} 方升起。
    - Interaction
      - {"version":1,"type":"fill_blank","grading":"exact","blanks":[{"id":"east","answers":["东"]}]}
    - Explanation
      - 太阳东升西落。
    - Practice 1
      - ……
```

原每个 Example 至少 7 道 Practice 的结构约束不变。导入、来源包、安装都复用既有机械校验，不调用 LLM 生成题型或答案。

## 多步题与答案呈现

独立题库及课程中引用的题库题支持 `multi_step`（schema 1）。它是原大题的作答方式，原题 ID、版本、完整解析及复习卡保持同一份。每步保存原小问序号、题面、参考答案和 `text` / `fill_blank` 控件；原题中的公共条件保存在 `context`，编译器生成对应 HTML。

服务端只返回公共条件、已经作答的小问和当前小问。当前步通过判题或自主评分才解锁下一步；判错任一步立即结束本次大题，展开剩余小问和完整原解答。判题服务故障不当作答错，保留当前小问重试。每步提交、Show Answer 和自主评分请求携带 `step_id`，刷新、幂等重放和跨设备过期请求均核对当前位置。

复现类步骤（`text` / `fill_blank` 且 `grading: semantic`）沿用高阶学习者权限与自主评分开关，空白作答时提供 Show Answer。它只显示当前步参考答案和解析，刷新仍停在这一小问；只提供“做对”（5）和“做错”（1）两个反馈键。做对解锁下一问，做错展开剩余小问及完整解答。下一步须重新显示答案再自评，复刻步骤继续正常判题。中间步骤的 5 只表示本步做对，不会提前停止整题推送。

中间步骤记录作答、自评和用时，不单独排期。全部步骤做对时整题返回 5 并停止推送，适用于首次学习、到期复习、提前练习及自评与普通判题混合的轮次；5 不进入 FSRS。任一步失败则整题判错，沿用普通错题的排期及并发版本保护。题库练习和复习试卷共用这些规则，整题只记录一次结果，纯普通判题不计入自主评分统计。复习仍从第一步开始，旧 attempt 保留冻结题目快照。Show Answer 的答案归属当前小问块，已自评小问保留已显示的参考解答，不展示虚假的空作答框。

结果保留 `multi_step` 复习接口：`version:1, mode:"whole", start_step:0, context_step_ids:[], first_failed_step_id, step_ids`。当前始终推送整题，从第一步开始；以后可由独立推送策略使用失败步骤与前序上下文，此次不启用。

选择题答案侧通过 `choice_feedback` 提供应选项 ID，未作答时不下发。应选项标绿，误选项标红，题干方向不影响标色。“应选”“你的选择”标签与整题答对／答错反馈分别呈现。

解析使用共用讲义字体、19px／1.9 行距（小屏 18px／1.95），按原小问或选项编号分段，保留原文、数学和层级。矩阵单独显示，长公式在自身区域横向滚动，避免撑宽页面；公式标点与公式同行。共用 `prepareAnswerContent`，不在导入产物中硬塞断行或逐题改写。

## 问答与填空的两种判题模式

`grading: "exact"` 对应复刻，服务端脚本严格比较；`grading: "semantic"` 对应复现，调用已有独立判题 LLM。选择、判断与配对始终由脚本判题。

复刻及选择、判断、配对在提交请求内完成机械判题，直接返回反馈，不等待 AI 工作队列或前端轮询。Lesson、Review、原子卡、独立题库和只含机械题的复习卷共用此分流；混合复习卷仍异步处理。答案保留在服务端，原判分、版本绑定、幂等和排程规则不变；复现保留异步 AI 判题。

复刻只合并 Unicode NFC、全角 ASCII 与空白差异；保留大小写、正负号、小数点、数学符号及上标差异，不做词义或代数等价推断。可用 `answers` 列出允许的精确写法。需要包装格式时设置 `extract_pattern`：正则必须恰有一个捕获组，完整匹配作答后提取该组比较，执行有超时保护。不要设置允许任意前后文字的宽泛模式。

```json
{"version":1,"type":"text","grading":"exact","answers":["42"],"extract_pattern":"(?:答案[:：])?\\s*([0-9 ]+)\\s*"}
```

```json
{"version":1,"type":"text","grading":"semantic","answers":["水由液态变成固态"]}
```

语义问答可省略 `answers`，此时沿用 `reference_answer`。语义填空在一条判题请求中提供题干、每空参考、所有作答以及“所有空都正确才判整题正确”的要求。

## 单项选择题

```json
{"version":1,"type":"choice","options":[{"id":"oa","text":"$3$"},{"id":"ob","text":"$4$"},{"id":"oc","text":"$5$"},{"id":"od","text":"$6$"},{"id":"oe","text":"$7$"},{"id":"of","text":"$8$"}],"correct_id":"ob"}
```

通用结构支持 2–12 个选项、唯一正确项；课程生成式转换默认六选一，书籍机械清理按原选项数量。ID 必须唯一，不能携带正确性含义。提交为 `{"selected":"ob"}`，空选、多选、未知 ID 和额外字段均拒绝，不计错。公共元数据不含 `correct_id`。

选项文本复用安全 Markdown 和离线 MathJax。Lesson 与 Review 按呈现标识确定选项顺序，刷新、恢复草稿和重试保持不变；后续呈现重新排列。正文只有一处可识别的下划线空位时，单选题也提供原位下拉框，与下方选项同步；多选、多个无编号空位及代码或公式中的下划线不作此绑定。下方选项支持鼠标、触屏、Tab 和空格；正文下拉保留原生方向键操作。两处均支持 Ctrl + Enter 提交。转换旧题与保留旧记录的版本规则见 [题库转换工作流](question-bank-workflow.md)。

可选 `shuffle:false` 保持原选项顺序，适用于原书解析按 A/B/C/D 指代的题目；省略时沿用原随机顺序。

## 多项选择题

```json
{"version":1,"type":"choice","multiple":true,"shuffle":false,"options":[{"id":"oa","text":"甲"},{"id":"ob","text":"乙"},{"id":"oc","text":"丙"}],"correct_ids":["oa","oc"]}
```

复用 choice 控件并显示复选框。提交 `{"selected":["oc","oa"]}`，集合完全一致才判整题正确；少选、多选、错选均判错。空数组、重复或未知 ID 视为无效作答。原单选 schema 与字符串提交保持兼容。`correct_ids` 留在服务端，不进入公共元数据；单选和多选均由脚本判分。

## 判断题

```json
{"version":1,"type":"true_false","statements":[{"id":"a","text":"$2+2=4$","correct":true},{"id":"b","text":"$3+3=7$","correct":false}]}
```

1–20 个判断项。每项使用真正的 JSON 布尔值。前端呈现逐项正确/错误选项；服务端记录逐项反馈。提交 JSON 形如 `{"a":true,"b":false}`。

## 填空题

数学等价式或答案不唯一的填空使用 `grading:"semantic"`。判题同时收到按空位整理的参考表达和原参考答案/解析；清洗阶段不重新解题。

```json
{"version":1,"type":"fill_blank","grading":"exact","blanks":[{"id":"a","label":"升起方向","answers":["东"]},{"id":"b","label":"落下方向","answers":["西"]}]}
```

题干写 `太阳从 {{blank:a}} 方升起，从 {{blank:b}} 方落下。`。每空标记必须恰好出现一次，不能放在 `$...$`/`$$...$$` 内。1–20 空，按题干位置显示输入框；`label` 可选。复刻填空可逐空设置 `extract_pattern`。提交 JSON 形如 `{"a":"东","b":"西"}`。

## 配对题

```json
{"version":1,"type":"matching","direction":"both","fixed_side":"left","left":[{"id":"l2","text":"$2$"},{"id":"l3","text":"$3$"}],"right":[{"id":"r9","text":"$9$"},{"id":"rx","text":"干扰项"},{"id":"r4","text":"$4$"}],"pairs":[{"left":"l2","right":"r4"},{"left":"l3","right":"r9"}]}
```

- `pairs` 定义 1–20 个框与服务端正确关系；两侧选项各不超过 40 个，每侧数目均不得少于框数。
- 每侧 ID 唯一，正确关系一对一。每次作答中每个选项只能用一次。
- `direction` 为 `forward`（默认单向）或 `both`（双向）。箭头表达题意；判题仍按给定关系。
- `fixed_side` 可为 `left`、`right` 或省略/null。预填侧从标准关系取得框内初始内容并锁定，另一侧保留全部候选与干扰项。
- 两侧都可编辑时，整行交换不影响正确性。候选区与框均支持拖动，另有点击选项再点击框、上下移动按钮，触屏不依赖拖动。
- 已占用的框拖到另一框会交换该侧内容，拖回候选区或直接点击该框会移除。另一侧不随之移动。
- 判断项和配对选项的 `text` 沿用作者 Markdown 安全渲染、相对 PNG 与离线 MathJax；导入生成 `html`。不要手写 HTML 或引入外部脚本。

提交形如 `[{"left":"l3","right":"r9"},{"left":"l2","right":"r4"}]`。标准关系、布尔答案、精确答案与正则留在服务端；公共元数据只含显示信息和明确预填的那一侧。

## 状态兼容与验收

结构化答案序列化成 JSON 字符串，继续使用原 2000 字作答上限、草稿键、尝试 ID、版本检查、幂等提交和重试机制。空项、重复选项、未知 ID、修改固定侧都会在服务端拒绝，不计为普通错题。总长度上限包括 JSON 结构，请控制项数和答案长度。

标准参考本身应是能直接填写的答案；如果正则强制包装且无法接受裸参考，游客浏览模式不会猜测包装。此题仍可正常人工作答。

`tests/test_question_types.py` 验证导入与判题；`scripts/shared_features_fixture.py --output <D盘新隔离目录> --real-judge` 和 `shared_features_acceptance.mjs` 验证浏览器 Lesson、Review、草稿、移动端及真实语义判题。合成内容不得发布到正式课程。
