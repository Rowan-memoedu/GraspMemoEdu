# 统一原子点与组卷复习

整合原子提取训练和独立题库的顶部复习页。综合范式的课程 Review 保持原实现。已支持预生产的 Practice 变式导入、点与卡的关联、可变设问选择、动态组卷及 A/B 提交模式。数学题库接入独立后台按需补充两个同组 Practice，见 [变式补题](review-variant-production.md)。原子设问使用[本地生产与机械导入](atomic-question-production.md)，其服务器按需生产尚未接入；AI 跨题库归并尚未启用。

## 记忆点与来源策略

- 原子卡、变式卡与打包复习卡遵循[统一 Flashcard 模型](topic-training-modes.md#统一-flashcard-模型)：单点与多点只由 `point_ids` 的关联集合决定，共用卡片机制，不以名称或生成来源硬编码为不同类型。关联点数变化时按同一套规则重新判断适用条件。
- 全站共用机械生成的点标识，稳定绑定来源种类、题库/Topic、内容版本及原点/原题 ID；学习状态按用户隔离。
- 题库在首次有效判题、自评完成或用户点击题目右上角 `⊕ 加入错题本` 时创建标记，单纯打开题目和 Show Answer 不创建。旧已学题首次进入统一复习时补关联，不改评分和到期时间。
- 手动加入未学题只登记 `training_memory` 的待学行（`mastered=0`、`revision=0`、`card_json=NULL`、立即到期），不产生作答、评分或 FSRS 状态；错题本和组卷沿用同一排期事实源。首次有效作答正确记 3、错误记 1，再从空卡初始化 FSRS。重复加入不改变已有排期，也不撤销用户已经选择的停止推送。
- 原子初学答对 null、6 小时后首次复习，错题 1；正式复习正确 3、错误 1。组块间隔、暂停及学习条件保持。
- 题库第一次普通作答即正确仍记 5 并停止推送；先错后对记 3。评分 5 不传给 FSRS。变式首次出现不重新触发初学规则。
- 已有 `topics` 点状态及 `training_memory` 仍是排期事实源。统一层通过原有 `_grade` / `_complete` 结算，不复制调度公式或批量改写历史。
- 高阶学员可直接练习题库中关联原子点的卡片，跳过这些点的已学和掌握程度门槛；普通学员仍遵循原限制。内容权限、暂停、在途训练和复习占用不受此资格豁免。直接练习中的未学点沿用原子初学评分（答对不评分、六小时后首复习；答错记 1），仅实际作答改变点状态；打开卡片不会补造已学记录。
- `review_points` 不含教学正文；`review_variants` 只存已编译、已审核的后续卡片。预生产复用 Example→Practice 的原题与解析输入方式，再通过私密 `scripts/import_review_variants.py` 导入。整批事务验证原题、原版本和已存在的点，失败回滚、重试不重复；公开网页不能安装。题库变式的答疑以不可变变式 ID 绑定正文快照，不能误用原题或其他点的变式。

## 选卡和卷型

`config/review-paper-types.md` 是唯一卷型配置源，按学科提供稳定 ID、用户可修改的名称、限时（整数分钟）、启用和题型数量。启动时严格校验，配置无效不得部署。新配置随应用发布生效，在途试卷保持快照。数学初始卷型为 8 单选、3 多选、3 填空、8 单选+3 多选、8 单选+3 多选+3 填空，默认分别为单选专项卷 20 分钟、多选专项卷 12 分钟、填空专项卷 12 分钟、选择综合卷 32 分钟、客观题综合卷 45 分钟。

每种卷型按可用点组成多份确定性的候选，同卷型各卷之间不重复用点，显示为卷一、卷二等；不同卷型之间仍可重叠。优先逾期较久的点及较少使用的设问。单点卡与多点卡按同一套规则参与组卷：每张卡按自身题型占一个题目名额，并占用全部关联记忆点；同卷内任意两张卡的关联集合不得重叠，同点不同题型也不能重复凑数。匹配在必要时回退重选，避免先选一张卡导致其他题型无法满足。每张卡保留整卡判定，结果分别更新全部关联点；单独复习同样使用这些卡片。

## 共用树状目录

目录选择器在同一学科下显示课程和题库，分别进入已有学习页和题库页。复习页中的单卡统一列在“原子卡片”，不再按课程原子内容和题库来源分成两个展示区。学习、题库和复习共用 `web/task-tree.js` 及原任务卡代码、样式；复习不复制一套树形控件。

每个单卡入口仅打开当前卡片。IDEA Check、Hyperskill 回传与网页判题共用 `learning-ui.js` 的复习目录、进度和阅读容器，作答区调用各自判题适配器。题库的章节和题组只用于定位来源，不会把同组其他题目带入这一轮单卡复习。重载外部判题卡片保留同一作答轮次，返回“复习”列表；题库浏览位置不受影响。

复习目录所有层级默认展开，用户仍可手动收起，当前页面会保留其选择；学习页、题库页和指南的默认展开规则不变。

原子来源直接使用 Catalog 的课程、单元与 Topic 关系，保留学习页内部层级，并增加课程名称根目录。题库来源直接使用原题库的分组、父子关系和顺序，并增加题库名称根目录；没有可复习内容的分支不展示。进行中的单卡复习留在对应来源节点。组卷以 MD 定义的卷型名称为根目录，子节点是可直接开始或继续的卷一、卷二等，开始后编号保留。来源 ID 加命名空间，不同课程或题库中相同章节 ID 不会冲突。

管理员“全部卡片”预览同样使用这套树形投影，通过既有材料入口访问卡片，不创建复习组卷或改变排期；普通身份不能访问该全量投影。升级前进行中的单卡可从已冻结的题面来源恢复目录位置。

候选卷可重叠。浏览不创建学习状态、不占用题目；开始时重新核验并占用相关点，冻结题面、选项、记忆状态版本和提交模式，FSRS 不变。所有题型数量都满足才提供固定卷型；其余点保留单卡入口，按一题整卷提交，不等待凑满而延误复习。数量按记忆点去重。

一份卷作为一次打包呈现，原子来源在开始时检查并更新组块展示时间；同卷的单点题可属于同组块，跨复习仍遵守 180 秒间隔。题库没有组块，不人为增加此间隔。已在旧原子页面进行中的复习保留继续入口。

## 提交模式和恢复

- B（默认）：允许导航题目、修改未提交草稿，手动交卷须全部有效作答；超时自动交卷允许未答题。后台逐题判分，全部成功后在同一事务分别更新各点；没有整卷统一评分。交卷完成前不公开中间判定或答案。
- A：仅高阶学习者且拥有 `review_question_mode` 权限时可在设置选择。每题提交后显示反馈并更新对应点，其余题不受影响。设置只影响新试卷；资格被撤销后，进行中复习也不能继续调用逐题接口。
- 草稿服务端小批量保存，浏览器按身份和试卷保存未同步草稿；管理员继续使用内存学习存储，不写 Web Storage 或正式学习数据库。组卷倒计时和作答用时均只累计可见复习页面的时间。
- 判题失败不计错；成功的中间判定只在服务端缓存。服务端保留原提交信息，刷新、换设备或服务重启后仍可重试，不依赖原浏览器缓存。重试只处理缺少判定的题，并只为重新判题数量预留每日配额。提交 ID 幂等，网络判题不占数据库写锁。
- A 的已完成题立即释放占用；B 统一交卷后释放。限时到达前取消不把未答题记错，保留已完成结果。未启用限时的旧试卷、单卡保留 24 小时草稿占用规则；限时卷按累计活动额度处理，暂停期间继续占用对应记忆点，不能借草稿过期或取消避开交卷。判题中不因普通草稿到期中断。
- 来源版本、暂停、权限或记忆状态发生变化时，旧结果不应用到新状态，提示重新选择。普通题库和旧原子入口也检查占用，避免重复排期。

## 内容块限时

`content_timing.py` 和 `web/content-timer.js` 提供可复用的限时能力；没有配置时不启用。本次只对组卷启用整卷总限时，原学习、独立题库训练和单卡复习均不计此倒计时。

- 开卷时服务端保存名称、分钟数、剩余额度和超时策略。进入页面开始计时，离开页面或切后台暂停，再进入继续剩余时间，不重置整卷额度；后续 MD 或设置修改只影响新卷。
- 默认到时自动交卷，使用截止前同步到服务端的答案。未作答或未完成结构化作答的题直接记错，不调用判题服务；有效答案复用原判题、配额和排期。逐题模式仅结算剩余题，已完成题不重复评分。
- 高阶学习者可在设置选择“超时仅标记，继续作答”。服务端校验资格；资格被撤销后恢复强制交卷。普通学员与游客不能用直接请求绕过限制。
- 客户端倒计时触发状态同步；服务端在状态读取、复习列表、保存草稿和取消时也核对已用额度，到时拒绝改写草稿。页面每 5 秒确认活动，正常退出通过 keepalive 保存暂停；关闭异常或断网丢失退出通知时，15 秒活动租约到期后自动暂停，不持续扣除离线时间。同一试卷同时只允许一个页面计时，旧页面迟到的暂停请求不能暂停新页面。
- 判题等待不继续扣除已交卷时间。判题失败仍按原规则重试，不把服务故障判成学习错误。队列或每日配额暂不可用时保留草稿、截止时间和占用，显示待提交状态，后续读取重试；不得恢复编辑或重复结算。
- 定时元数据随试卷和备份保存；旧的进行中试卷没有限时元数据，继续原行为。

## 复现题自主核对

`question_types.is_reproduction` 统一以 `text` / `fill_blank` 和 `grading=semantic` 判断复现题，旧无 interaction 的问答题保持语义判分。`grading=exact` 的复刻题不开放 Show Answer。高阶资格、`training_self_rating` 权限和设置开关均须满足；服务端重复校验。所有学习、原子卡、题库、单卡及组卷入口都支持，结构化填空所有空均为空时可显示答案，部分作答仍走正常提交。

课程学习、范式复习和原子卡沿用原来的正确／错误及排期规则：自主评分 1 对应错误，2–4 对应正确，不用每题自评分替换模块掌握度。组卷自评分作为草稿，在原 B/A 提交时结算，并保持点占用及一次排期规则；仅查看答案不评分。题库保留原有 1–4 自评分和独立停止推送功能。目录区仍称“我的错题本”，卡片入口统一称“复习任务”。

问答题的 Show Answer、反馈和历史只展示解析，不返回或展示参考答案字段；私有判题依据不改写。选择、填空、判断、配对题在已有答案可见阶段统一展示参考答案，从既有正确选项、空答案、判断值或配对关系机械读取，不额外生成内容。后端共用 `reference_answers.py`，前端共用 `self-assessment.js`。参考答案公式复用离线 MathJax 渲染，解析中的 SVG 字形引用在挂载时隔离，避免重复显示同一解析时引用冲突；学习 Show Answer 不重复挂载解析。

## 数据、备份和验证

新增表为 `review_points`、`review_variants`、`review_papers`、`review_reservations`、`review_card_uses`、`review_paper_preferences` 和 `paper_submissions`，随既有 SQLite 备份。恢复和服务启动将中断判题标为可重试，保留成功的中间判定。文档和卷型配置由源码 Git 版本保存。

后端发布包必须包含 `config/review-paper-types.md`；只替换 Python 包而遗漏配置会导致启动校验失败。升级自动创建新表，既有排期及评分历史不迁移、不重算。

接口位于 `/api/review-papers/`：inbox、open、state、activity、reveal、draft、submit、cancel、preferences。沿用身份、学科、内容、功能、Origin、请求体及判题配额边界。没有内容生成、导入、跨题库合并或修改排期的公开接口。

专项测试 `tests/test_review_papers.py` 覆盖双模式、资格和身份隔离、重叠选择、跨题型匹配、稳定点和变式、初学政策、失败重试、备份、草稿、占用与到期释放。真实判题与浏览器验收仅使用隔离合成内容，不消耗正式学习记录。

`tests/test_review_timing.py`、`test_content_timing.py`、`test_review_hierarchy.py` 和 `test_review_directory_api.py` 验证限时与未答判错、资格撤销、旧草稿兼容、来源权限及目录一致性。`scripts/review_tree_fixture.py` / `review_tree_acceptance.mjs` 使用真实一分钟倒计时、真实语义判题和桌面/手机浏览器验证自动交卷与不中断模式。
