# Practice 持久队列

每个学习者、Topic、Example 共用一条长期题目队列。Lesson 和复习从同一队列取题，FSRS 仍以 Example 为单位决定下次推送时间。

## 算法

1. 新 Lesson 的前三题固定取前三组首题（展平后的第 1、4、7 题），按顺序展示。首次创建长期队列时只放这三题；若已有队列，保留其他待推送题和展示记录，前三题仍按新轮次规则取出。复习独立初始化队列时保留五组各随机首抽一题的规则。
2. 实际展示下一题时，从队首取出；本轮已展示题跳过并保留到下一轮，确保同轮不重复。只看历史、刷新或重复请求不取新题。
3. 某组第一次判错时，把该组另外两题按组内顺序追加到队尾；已在队列中的题不重复入队。记录“该组已补题”，跨 Lesson、复习、暂停和解锁一直保留。新 Lesson 第 4 次错会立即暂停，此次错误不再追加题目。
4. 队列没有本轮可用题时，随机选一道未推送、未排队且本轮没出现过的题；全部推送过后，选最后一次推送最早的题。
5. 每轮只按当前题量需求取题。轮次结束不清空队列；下次到期继续。

“推送”指实际展示题目，不是预先放入队列。展示后主动暂停、未作答，也算已推送；不会因此记错。先入队的补题保持队列顺序，补题规则可使此前见过的同组题早于未见题再次出现；未见优先和最久未见优先用于队列不足时的补充。

最久未推送以递增展示序号比较，不依赖系统时钟。一个题目每次实际展示都会更新序号，因此连续复用时不会一直选择第一次做过的同一题。

例如新 Lesson 先排 `[1.1, 2.1, 3.1]`。若 `1.1` 答错，将 `1.2、1.3` 放到队尾，本轮目标由 3 增至 5；其余四题都对则完成。若后续再错，目标依次增至 7、9；同组已经补过时不重复入队，缺少的题按未推送/最久未推送规则补足。每次实际展示都会更新长期队列，复习继续使用这些记录。

## 题源与单轮评分分开

| 场景 | 本轮累计错误数 | 本轮目标题量 | 完成后评分 |
|---|---|---|---|
| 新 Lesson（15 题分组库） | 0 / 1 / 2 / 3 | 3 / 5 / 7 / 9 | 4 / 3 / 2 / 1 |
| 已开始 Lesson / 非 15 题旧库 | 0 / 1 / 2 / 3 | 2 / 3 / 5 / 7 | 4 / 3 / 2 / 1 |
| 复习 | 0 / 1 / 2 | 1 / 3 / 5 | 4 / 2 / 1 |

Lesson 第四错、复习第三错或主动暂停，沿用原有 Topic 暂停机制，不产生本轮评分。游客不能主动暂停。长期队列的“首次错组补两题”决定题源，本轮每次错误导致的题量变化仍由 `practice.py` 决定，两者互不代替。

## 数据与兼容

- `practice_queues` 按 `learner + topic + module` 隔离，保存课程版本、队列、已补题组和展示顺序；不通过公开接口返回未来题或队列。
- 轮次保存 `practice_queue_version=grouped-v1`；新 Lesson 另存 `practice_policy=lesson-v2` 的 3/5/7/9 策略快照。没有策略快照的既有轮次按 `lesson-v1` 继续。取题、保存当前页面和错误补题都复用原 SQLite 事务。判题失败、重复提交、过期或已暂停轮次的迟到结果不补题。
- `source_practice.group/member` 优先作为分组依据；没有分组元数据的 15 题旧库按原顺序每三题一组。其它合法旧题库保留原有抽法；部分或错误分组元数据拒绝加载。
- 升级前已开始的 Lesson/复习不改变题序，待新轮次采用新机制；不推断或回填旧历史。课程和队列规则版本不符时保留原数据并拒绝操作。
- 暂停、解锁、重启和整库备份保留队列。主动清空某个 Topic 的学习记录会同时清空该学习者的队列和组内补题标记，不影响其他身份。
