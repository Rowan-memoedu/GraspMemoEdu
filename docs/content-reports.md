# 内容块答疑与质量反馈

- 学员和管理员在学习、复习、题库题目及解析中使用同一组入口。红色“内容质量反馈”在蓝色“请求答疑”上方，两行文字间隔为两倍行高；两者均可填写说明或留空提交。
- 共用组件为 `web/content-report.js` 的 `helpableContent`；需支持选中文字纠错时用 `reportableContent`。组件绑定内容块 ID 和不可变内容版本，不通过界面文字猜测位置。原子训练暂停和判题中的学习按钮锁定不影响这两个入口。
- 两类提交共用 `/api/help-requests`，`kind` 为 `help` 或 `quality`。旧请求默认 `help`，旧记录的重试仍保持幂等。共同使用每个身份每分钟三次的限制，重试不重复保存。
- Topic 使用 `topic_id`、可选 `question_id`；支持题目、解析、指导章节和记忆组块。独立题库另携带 `bank_id`、`group_id`，`topic_id` 必须是服务器对应的 `training.<bank_id>` 权限 ID。
- 后端核验学员资格、内容权限、所属学科、内容版本及题目位置，再从服务器内容取得标题和正文快照。提交不修改学习进度或复习排程。
- “答疑”统一放在导航栏的题库与指南之间，继承原导航间距；头像菜单不再保留“答疑请求”。`#/qa` 或学科内 `/qa` 按身份显示管理员收件箱或学员自己的答疑；原 `/help-requests` 地址重定向到同一页面。
- 每条记录左侧显示提交时的内容块和问题，右侧按发送顺序显示完整对话，双方都有文本输入框。“发送回复”新增消息；“回复这条”关联此前消息；“修改”仅对自己发出的消息显示，并更新该条消息。编辑早先的回复不删除后续对话，管理员仍只管理当前归属自己的学员。
- 学员的详情页 `#/subjects/<subject>/qa/<report-id>` 显示原内容、问题及回复。管理员的“打开对应内容”进入 `/topic/<topic-id>/content?block=<block-id>`，列出完整 Topic 并聚焦目标块，包括全部备用 Practice 与解析；题库提交定位到对应题组。刷新保留位置。旧版本已不可获取时明确提示，并继续在答疑记录保留原始快照。
- `GET /api/help-center` 提供分页、单条详情和 `summary=true` 未读摘要；旧 `/api/help-requests` 只读接口保留兼容，仍只供原归属管理员使用。
- 两个弹窗保留提示语和主文本框，中间提供四个复选项，初始全部不勾选。`categories` 为可选列表；质量反馈支持 `formatting/factual_error/unnatural/other`，答疑支持 `missing_prerequisite/derivation_steps/motivation/other`。缺少前置知识时展开独立输入框，`prerequisite` 最多 1000 字，主说明仍最多 4000 字，两者均可留空。
- 事实性错误、不自然内容、推导跳步和思路动机选项展开原内容预览；`POST /api/help-requests/preview` 与提交共用内容定位及权限核验，只读，不占提交频率、不初始化学习状态。预览支持逐行点选、取消及鼠标拖框多行选择，也可不选。
- 行选区保存为 `selection_version=1` 的 `[token,start,end]` 数组及原 HTML 的 SHA-256 `selection_hash`。文字偏移按 Unicode 码点计算，公式、图片和图表为原子 token。屏幕换行不改变锚点；服务端验证范围及快照哈希后随请求存储，最多 256 段。仅答疑提交的请求体上限提升为 64 KiB，其余接口保持原上限。
- 学员和管理员共用分类、前置知识及原文高亮的展示。旧记录没有分类、标注时按原样显示。未选择分类或选区、空白说明仍可提交；选择隐藏时不提交其选区，取消弹窗清空本次草稿。
- 旧记录优先恢复准确版本并核对保存的正文；无法核实时明确显示原文本快照。新记录保留提交时 HTML 和数学样式；正文更新或移除后仍显示原快照。浏览不初始化学习服务或创建题库尝试。
- `POST /api/help-replies` 仅接受归属管理员，回复不能为空。每次回复带 `request_id` 和 `expected_revision`，重试幂等、并发冲突返回 409；修改回答保存新版本，不覆盖旧回复。`help_replies` 保存版本记录，随网站数据库备份。
- `help_reply_reads` 按学员和具体回复版本保存阅读状态。`POST /api/help-replies/read` 只能确认自己已存在的回复版本；旧版本的阅读回执不会吞掉新回复。导航显示未读数量；网页可见时每 30 秒刷新摘要，学员停留答疑页时自动更新新回复。回答实际进入视野后确认已读，也保留手动标记入口。
- 学员必须保有学员资格和 `request_help` 功能权限；答疑数据不按当前 Topic 权限重新绑定。记录、总数、未读数、分页和单条读取均按身份过滤。答疑回复与已读状态不会改变学习进度或复习排程。

## 多轮对话与主题更新

- `POST /api/help-messages` 对学员和归属管理员开放。无 `message_id` 时追加消息；`reply_to` 可指向同一对话的既有消息。带 `message_id` 和 `expected_revision` 时只编辑自己的消息，冲突返回 409。每次操作使用独立 `request_id`；重试不会重复发出，复用标识修改内容被拒绝。回复不能为空，最多 4000 字。
- `help_messages` 保存消息身份、作者、角色和关联；`help_message_versions` 保存全部编辑版本；`help_thread_events` 保存每次发送/修改的序号。旧 `help_replies`、`help_reply_reads` 原行保留，升级时将原回答及其所有版本导入同一条消息，迁移可重复运行。旧 API 保留兼容，旧客户端的已读回执只确认旧回答。
- 双方的导航栏显示未读对话数，自己的消息不算未读。`POST /api/help-messages/read` 只能确认自己有权访问的对话及真实事件序号；旧序号不会吞掉新回复。只在对话实际进入视野时自动确认，也可手动标记。可见网页每 30 秒刷新摘要，`activity_key` 同时反映消息和正文版本变化，答疑页自动更新且保留输入草稿。
- 曾提交答疑或质量反馈的 Topic/独立题库有新版本时，相应记录显示“有更新”，并产生一次未读提示。提交时原文和高亮始终保留，“查看更新后的对应内容”只读取所提交的那个块。再次更新会再次提示；已读后“有更新”仍保留。以整个 Topic/题库版本为单位，不要求提交的块本身发生变化。
- `source_version` 与 `help_content_baselines` 绑定提交时的 Topic/题库版本，避免将转换题库或可变设问的独立版本误当作 Topic 更新。新旧正文缺失时保留快照；旧独立题库版本来源不明确的记录在升级时以当前来源作为基线。`help_content_reads` 按身份记录已看见的更新版本，过期回执不能覆盖新版本。
- `GET /api/help-content?report_id=...` 读取当前对应块，核验对话归属、测试材料策略、所属学科以及当前内容权限，不开放任意块、不解锁学习或复习。所有新增表包含在既有 SQLite 备份中。
