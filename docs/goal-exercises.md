# 目标隐性练习与动态解锁

整篇目标题独立保留在题库中，只用于提取领域学习需求和课程完成后的记忆点映射。教学课程从完整教材章节、专题和词条组生长，作者不接触目标题、答案或逐空关系。课程图谱引用题库中的题组；题面、作答记录与题组身份只有一份。协议 3 的课程图谱可包含同学科的题组成员，题组和 Topic 继续使用同一套前置边与跨图环路检查。

图谱页面从记忆点引用派生对应 Topic 到题组的前置关系，标记为记忆点条件。这些关系参与统一环路检查，但不额外要求相关 Topic 的所有补充内容都已完成。管理员预览中的解锁读取当前登录会话的临时学习状态。

## 同一套记忆点与评分

题库题目的 `point_ids` 可引用已有原子记忆点，格式为 `topic_id/point_id`。一个关联是单点卡，多个关联是打包卡，不增加目标专属卡片类型。引用在加载时校验，不能指向未知点或其他学科；学习者必须拥有各点所属 Topic 的访问权限。

`assessment: {version: 1, item_points: {control_id: [point_reference]}}` 与 Topic Flashcard 使用同一合同。一个空可考查多个点，一个点可由多个空共同检验。评分通过共享的 `AtomicLearningService._grade` 更新原有 FSRS 状态，一次作答每点至多更新一次。普通打包复习、综合复习卷与目标题共用这一逻辑。

没有被实际考查的词义或篇章理解点只列入解锁前置，不放入题目的评分关联。题库不为关联题创建 `training_memory`，也不为整篇文章增加第二份 FSRS 状态。已有不关联原子点的普通题库题目保留原行为。

## 内容属性与触发条件

题组可声明：

```json
{
  "unlock_policy": {
    "point_ids": ["topic-a/point-1", "topic-b/point-2"],
    "min_successful_reviews": 1,
    "min_stability_days": 7,
    "min_retrievability": 0.9
  }
}
```

这些阈值是本轮选定的产品规则。所有前置点必须学会、未暂停、至少有一次达到首次复习间隔的成功复习、最近复习成功、稳定性至少 7 天、当前保留度至少 0.90。成功间隔复习使用既有学习记录；当前保留度由官方 py-fsrs 计算。

解锁没有永久完成标记。学习页、题库页、打开和提交接口重新读取同一份学习状态；遗忘、答错、暂停、权限变化或正文版本变化都可以重新锁定。已提交作答的历史保留。正式评分发生前还核对各点的版本与状态指纹，旧作答不能覆盖后来发生的学习。

第一次完成已解锁目标题时，关联点不必到期，仍通过原有逐点评分进入 FSRS。之后题库中的未到期重做记录为练习，不通过连续提前作答反复增加稳定性。普通关联打包题只有全部被考查点到期才进入综合复习；到期题和目标的区别在推送条件。

目标完成状态与当前解锁状态相互独立：已完成的题组仍可能重新锁定，界面保留历史并显示当前条件。解锁前置集合可以大于实际评分集合。

## 课程生产

`scripts/produce_goal_course.py` 复用现有 `CodexExecClient`。每次规划、作者生成和教学审查都是独立、禁用工具的执行，保存精确请求、原始响应与执行凭据。旧的目标原文/空位/答案输入协议不再接受。

角色分为三个独立边界：

1. 需求提取只读取私密目标题；交给教学侧的独立文件严格为 `{role: "domain_objectives", learning_objectives: [string]}`，只有领域中立目标。
2. 教学侧只读取完整材料单元及上述通用目标。目标所需知识只是课程所有知识的一部分；不能把教材压缩成答案讲解。完整章可自然组织为多个自包含 Topic，不预定 Topic 数量或卡片数量。各 Topic 应提供充分且多样的多点综合应用，不为凑数拼接无关记忆点。
3. 教学完成后，映射侧读取全部课程点与私密目标题，分别决定解锁前置和实际评分关联。课程作者不接收任何映射结果。

教材选择题给定的选项或答案只约束原题，不自动证明其他表达在语言中都不成立。转换成独立卡片时须重新确认题面是否足以限定读法；允许零冠词、事件可数读法或其他自然解释时，答案与判据要接受并解释这些替代形式。不能用未写进题面的“具体一次便必须用定冠词”等暗含条件排除合法答案。发现缺陷后保留原响应及审查反馈，从原来源重新生成，不手修候选；通用 Prompt 修订须在本轮在途请求结束后重新绑定指纹。

### 教学材料接口

唯一教学输入是 `materials-manifest.json`：

```json
{
  "schema_version": 1,
  "role": "teaching_materials",
  "course": {"id": "course-id", "title": "课程名", "subject_id": "english", "description": "教学范围"},
  "learning_objectives": [],
  "units": [{
    "unit_id": "source-unit",
    "title": "完整章或专题",
    "role": "teaching_source",
    "source_refs": [{"path": "原始来源绝对路径", "sha256": "来源哈希", "line_start": 1, "line_end": 100}],
    "content_path": "units/source-unit.txt",
    "content_sha256": "完整单元文件哈希",
    "completeness": {"kind": "complete_chapter", "boundary": "自然单元边界", "subunits": [{"id": "section-a", "title": "自然小节"}]},
    "teaching_scope": ["完整教学范围"]
  }]
}
```

`completeness.kind` 还可为 `complete_topic`、`complete_reference_entry` 或 `external_reference_summary`。最后一种明确表示新整理的外部参考摘要：边界应说明完整自然参考范围，不能冒称原库全文、网页逐字转录或包含全部例句。摘要性质和正文一起进入作者输入。小型隔离输入可用内嵌 `text` 代替 `content_path`；正式材料用冻结文件及哈希。`source_refs` 可同时保留 Markdown 行范围和 `rem_ids`，只存于材料清单，不传给作者。教材例题答案属于完整教学材料；私密目标题答案、题号和情境不得混入该材料。

作者输入使用白名单投影。`target_required`、`assessed_by`、`blank_ids`、目标源角色、旧检索计划等在过滤前直接拒绝，不能静默丢弃后冒称隔离。完整正文按单元保留，不改为目标词命中的局部窗口。真实图片仅给出路径不等于已读；纯文本执行需要独立核实的原图文字转录，无法转录时该单元保留具体阻塞。

规划始终读取该组全部完整来源。单 Topic 作者读取本组完整计划，以及自身全部 `coverage` 角色所涉及的完整自然小节和原始前言；重复与相邻小节只保留一次，正文不切句、不使用检索窗口。自然标题缺失、重复或顺序不可靠时回退整个来源单元。运行目录保存完整来源，作者输入的 `source_selection` 另记原始完整边界、逐节精确行范围和正文哈希；该投影随请求整体绑定指纹。所有自然小节均被选择时保留原输入身份，既有完整单元 Canary 不倒改。外部参考摘要仍明确标为摘要，不因分节改称原库全文。

### 生产、原生导出与编译

```powershell
& 'D:/AppData/GraspMemoEdu/venv/Scripts/python.exe' scripts/produce_goal_course.py --source '<materials-manifest.json>' --output '<新运行目录>' --workers 2
& 'D:/AppData/GraspMemoEdu/venv/Scripts/python.exe' scripts/prepare_goal_course.py --run '<运行目录>' --output '<新编译目录>'
```

可用 `--unit <unit_id>` 选择完整教学单元，`--plan-only` 只完成规划，`--topic <id>` 接续该单元的指定 Topic。材料库可声明 `curriculum_units: [{unit_id,title,source_unit_ids:[]}]`，把同主题互补来源合并规划；每个来源恰好归入一个教学组，不按来源份数重复建 Topic。规划只做机械结构和完整来源范围检查，保留真实生成凭据，不另设计划语义审核。作者独立生成各 Topic；一次独立教学审查同时读取完整来源、计划和正文，评价教学缺陷，不增加逐题批准清单。计划与正文共用一个有界执行池，避免外层逐来源串行或嵌套线程池。已通过单元校验响应及凭据后直接复用；失败从同一冻结来源重新生成，新旧尝试均保留。未知执行结果不自动重发，手改候选不能作为通过证据。

Topic 按可迁移的实质概念与解释框架划分，训练模式、写作、改错或题型变化本身不构成新 Topic。知识与应用不默认成对拆分；原子 Topic 可在指导正文中讲例子，并用统一 Flashcard 做多点综合应用。Introduction 的标题与数量由概念子题决定，不能把记忆组块、原子点、Flashcard 等内部结构另建为指导节。规划逐自然来源小节声明主教学归属、应用或前置引用。实质正文须有主教学归属；只有在完整自然边界内确认为空正文的显式引用标题，才可仅由前置引用覆盖。标题带引用但仍有正文、边界歧义或纯应用覆盖均不获得该例外。

多单元课程先完成全部单元的概念计划，再由课程级协调阶段生成具体 Topic 前置、基础解释复用与职责冲突。唯一材料清单可附 `scope_dependencies: [{units:[source_unit_id], prerequisites:[source_unit_id]}]`；它只提示来源主题，不能直接变为图谱边。只有缺失某项先修便无法完成当前目标、且当前 Topic 不教授它时，才建立对应具体 Topic 的依赖；复用本身不自动增加完成门槛。作者收到相关提供者的目标/指导节摘要，不复制其基础记忆点，不使用跨 Topic 的卡片 `point_ids`。

职责冲突解决后，流程从真实计划与必要先修关系生成 `课程目录.md`，按先修顺序呈现每个 Topic 的教学目标、指导子题和可读来源名称；复用关系不会被扩大成学习门槛。正文不放路径、哈希或内部 ID，也不预写卡片或例题数量。规划 scope 中的来源场景只作覆盖追溯，作者仍按教学目标自主安排例子、题型和训练。

课程协调输入用可逆列式 JSON 减少重复字段名，完整保留所有目标、边界理由、coverage 和详细 section scope。字段列定义与完整输入哈希随请求传入，机械还原后必须逐项相等并匹配哈希；另存 `complete-coordination-input.json` 供回读。这不是语义摘要。当前 Exec 禁用文件工具，不能用本地路径冒充已经读取的细节；若完整输入仍超出安全容量，按完整知识域分段，并在判断具体跨域职责或先修时提供涉及的完整计划。

`--coordinate-only` 完成协调但不派发作者。可用 `--coordination-max-chars` 指定实际序列化请求的字符预算；该值不是模型 token 数，须根据模型窗口和输出余量预先选择。超过预算时按材料目录中的完整教学组分批，每对单元（含自身）恰由一个批次负责，实际传入双方全部计划。`partition.json` 绑定完整输入并验证所有单元对无遗漏、无重复；单份完整计划或完整计划对仍放不下时明确拒绝，不截断正文。每批调用共用有界调度、原始 Exec 凭据和接续逻辑，按完整局部输入与 Prompt 指纹存放；无关计划变化不强迫重跑输入相同的批次。

分批结果只做保留出处的机械合并，写入明确标识为机械汇总的 `combined.json`，不伪造单次 Exec 的 `accepted.json`。回读时重新验证所有批次原始凭据、逐条出处和整个图的环、引用提供者与覆盖规则；冲突或不一致直接保留，不能静默选择一条关系。协调结果绑定全部现行计划及 Prompt 的指纹，存在职责冲突时停止受影响作者派发。`--plan-feedback <本轮协调的 accepted.json 或 combined.json>` 将真实协调反馈交给受影响单元，从同一完整来源生成独立规划修订；旧计划和已通过的其他单元保留，失败或未完成修订不取代当前计划。正常作者使用成立的课程协调上下文，导出时再核对同一课程关系并合并真实跨单元 Topic 前置。不得用整章全连接、题型桥接 Topic 或未经生成的人工合并掩盖重复。

完全独立的已规划 Topic 可用 `--independent-topics-from <原 combined.json>` 和明确的 `--unit`、`--topic` 选择提前生产。入口回读全部原始协调凭据，要求所选 Topic 不出现在任何原主张中、没有本地前置，且其完整教学组不涉任何冲突的相关 Topic；完整来源、本组计划与空依赖上下文仍进入正常作者和一次独立审核。派发记录明确全局尚未通过。单 Topic 可导出真实原生源及阅读投影，全课程汇总编译和安装仍需最终协调；后续只在相关作者输入逐字段一致时复用，不能用此入口宽泛绕过冲突。

来源单元与课程单元使用不同身份域。新协调响应通过 `affected_topic_refs` 明确需改的现有 Topic，`topic_refs` 同时保留相关但不需改的提供者；受影响课程单元由真实 Topic 归属机械派生，不再让模型重复自由填写。原响应不修改。严格匹配完整局部输入、原 Prompt 与真实凭据的旧 accepted 可以保留原单元级语义，不据此猜出更细的受影响 Topic。旧终态拒项只有在凭据和原请求核对、机械失败重现后才可作为新请求反馈，另存来源绑定；未知在途结果、手改候选和无 accepted 的输出均不能冒充可复用批准。

`reference_resolutions` 只解析经完整来源确认的空正文交叉引用；普通有正文知识的调用走现有 `reuse`。输入另列机械派生的 `reference_resolution_cases`，保留 consumer 当前覆盖角色及详文 provider 候选，不推导硬前置边。consumer 仍错误声称 primary 时只能报告真实职责冲突，不能先填写假设修订后的 prerequisite 解析，也不能自引用。新清单和规则绑定新输入指纹；旧 accepted 只有在去除该可重算清单后全部原输入仍逐项相同、真实凭据及现行机械规则均通过时才兼容复用，原字节不改。

`--coordination-observations <报告JSON>` 可与 `--plan-feedback` 一起传入已有 subagent 的事实核读。报告必须绑定实际参与该轮协调的 accepted 文件、完整输入和原候选，且只涉及原响应明确要求修订的 Topic；它不授予批准。实际修订输入仅投影对应单元的发现与修复说明，并绑定报告哈希，其他单元的输入保持原样。候选、协调响应和原报告均不手改；最终按受影响单元归并修订，不为每条发现重复重规划。

原生范式抽样验收保留真实先修闭包。`validate_source_course.py --topic <id>` 在独立测试身份下，按现有 DependencyPolicy 取实际前置并通过正常 API 完成标明为调度 fixture 的前置学习，再验证选中 Topic 的学习状态与少量真实判题；不写伪完成记录、不改图谱。前置 fixture 和目标真实判题分别保存证据。截图工具可用第三个位置参数选中同一 Topic，完整闭包仍安装；管理员内容预览只证明呈现，不证明学员前置解锁或全程学习完成。

规划修订实际收到完整本组原材料、完整本组旧计划，以及冲突和观察明确引用的完整外部 Topic 记录。外部记录保留全部目标、边界、coverage、详细章节 scope 和原有前置，绑定原全计划与 Topic 哈希；不重复加入其无关兄弟 Topic，不截断相关记录或缩写词义。已核对的引用正文一并保留。`curriculum-feedback.json` 记录对应协调输入、反馈和上下文身份；部分受影响单元已经通过而其他单元失败时，同一命令只接续未完成单元，不重复生成已通过修订。回读原反馈始终验证其冻结时的真实旧计划和 Exec 凭据，不将后来已通过的修订误当成反馈来源变化；不属于同一反馈的后续改动不能借此复用。

独立来源核读发现的引用关系可用 `--source-findings <报告JSON>` 加入同一次课程协调。只投影来源 ID、原文证据和哈希等字段，回读完整输入验证引用确无正文、详文行范围属于真实自然小节、正文及哈希一致；不传本地路径，不把报告当作批准。协调必须把引用绑定到实际详文的主责 Topic，缺失或错误提供者均拒绝，旧计划把空引用当主教学时须报告职责冲突并重新规划；引用本身不自动生成图谱边。

本次纯引用规则允许上一代概念规划 Prompt 的有效结果做机械复检：先核对原响应与执行凭据，再按新规则检查并另存 `mechanical-revalidations`。原 `accepted.json` 和生成 Prompt 不变，复检不冒称新生成或语义批准；课程级冲突仍须由真实 Exec 重规划。更早的围题或结构层级规划不在此兼容范围内。

批量作者最多只有 `workers` 个任务在途，不预先排队全课程。基础设施或凭据异常出现后立即停止补位，取消尚未开始的 future，并保留已经运行的请求及其结果。

计划复用绑定单元自己的完整输入与 Prompt。运行根的 `teaching-input.json` 是当前材料目录，历次目录保存在不可变 `input-history` 中；增加或修订尚未规划的其他单元不会使既有计划失效。若任何已经冻结的单元输入发生变化，接续直接拒绝，不能静默沿用旧计划或覆盖原执行证据。

已规划材料发生真实补源时使用新的运行目录，并可传 `--reuse-plans-from <原运行目录>`。只有完整单元输入逐项相同、现行规划规则接受且原始 Exec 凭据仍可回读验证的计划才复用；变更单元从新完整来源正常生成。复用保留原 `accepted.json` 和响应字节，原始调用目录不搬移，另存来源路径、文件哈希与“未进行新生成”记录。已启动的目标阶段和未完成的原规划修订均不会被覆盖。开始新版前先确认对应旧调用已终态，避免相同单元重复并发。

已记录的独立 subagent 候选复核可通过 `--author-feedback <审查JSON>` 交给同一重试流程，必须精确选择一个教学组和 Topic。入口核对候选、计划及来源证据哈希，核对原生成凭据与完整作者输入，拒绝未知在途审核；外部报告必须明确不是批准、未修改候选且不替代正式 Exec 审核。发现的问题进入下一候选的 `previous_issues`，来源单列 `external-feedback.json`，不制造假的审核或拒绝凭据。已通过计划复用，旧候选字节保留，新候选仍需正常独立审核。

通用作者与审核规则要求题干完整自包含，不重复拼接问句；引用的选项字母或题号必须能在同学习单元解析，否则改用实际表达与理由，来源编号保留在追溯资料中。来源标题、选项答案和例句均需按定义、句法与语境检查，不能把单个答案推广成唯一合法形式。

复用同时核对冻结输入、执行证据和当前阶段 Prompt，保存 Prompt 指纹；修订通用规划或作者规则后，旧批准不会自动变成新规则下的批准。`OUTPUT/STOP-DISPATCH`（或 `--stop-file`）可阻止新生成/审核派发，在途结果仍保留。默认不重发未完成调用；只有人工已核实启动环境恢复，才使用 `--retry-failed-start --attempts 1` 开新尝试。该入口要求终态失败凭据、零模型事件、空最终输出和完全相同请求，保留失败凭据，不把基础设施故障变成教学缺陷。若生成已经成功，仅审核遭遇此类故障，就复用同一候选及生成凭据，在该尝试的 `review-retries` 中单独续跑审核；可加 `--review-only` 明确禁止规划与正文重生成。未知结果与凭据异常直接停止，不触发正文重生成。

实际可导入源文件是 `*.atomic.json`（既有结构化原子 schema 2）和 `*.v2.json`（既有作者 Topic v2），不是自定义平铺 Markdown。前者保留多 Introduction、独立 memory_chunks / memory_points / flashcards；后者保留 Introduction、Example、Explanation、Practice 的原生节点层级。v2 的每个 Example 至少七道 Practice 是现行队列的系统条件。

组块锚点只能引用原有 Introduction 正文的精确文字。作者提供引用，机械投影计算 Unicode 字符位置；重复文字须指定 occurrence。正文不匹配即失败，禁止在 Introduction 尾部追加组块/点清单来制造锚点。

`export/课程目录.md` 链接原生源与类型清晰的阅读稿。阅读稿按 Introduction → 记忆组块 → 记忆点 → Flashcard 层级展示，打包卡明确列出关联点；范式阅读稿保留原生嵌套。阅读稿只是可读投影，不冒充导入源或实际系统验收。

`export/point-catalog.json` 导出**全部**课程点，每行含 `point_ref`、Topic、Introduction、组块和点内容；状态为 `unmapped`，不携带设计阶段的拟考查关系。完成后的独立映射可以输出原生题库源，再用 `prepare_goal_course.py --goal-bank-source <path>` 一并机械编译。此可选步骤只检查格式、来源一致性与真实点引用，不重新判答案或生成逐题审查。没有目标题库时，课程仍可独立完成原生编译与隔离预览。

机械编译后从实际 Topic 的 `memory_chunks.points` 回读所有 `topic_id/point_id`，与完整点目录精确比对，防止映射只在作者源中自洽。目标题的点引用仍由既有统一图谱派生记忆点条件，不额外手工增加整 Topic 完成前置。

编译包声明 `semantic_review_performed: false`；教学生成审查与机械导入证据分别保留。测试材料在激活前标记，正式账号学习记录不改。只有隔离安装、实际系统呈现和相应学习行为验收完成，才可报告实际交付已验证。

首个已通过 Topic 可用 `prepare_goal_course.py --topic <id> --export-dir <独立导出目录>` 机械编译；导出状态明确标为非完整课程。`preview_source_course.py --prepare --bundle <编译目录> --output <隔离目录>` 使用真实课程安装器载入测试数据，随后以同脚本启动本地预览。`capture_source_course.mjs` 对照安装后的原生快照，回读完整内容目录、Introduction 顺序、全部题与解析及卡片点关联，再通过原生页面截取每节指导和覆盖全部组块的单点/多点卡及原文锚点。管理员单卡预览会重置临时学习状态，因此报告明确不证明正常学习完成，也不提交作答或替代真实判题验收。

截图使用本次独占的临时 Chrome profile，不读取用户 profile；记录 Node 与 Chrome 的 PID、创建时间及可执行路径，关闭后用已记录指纹并集和精确 profile 回读确认退出，清理未确认时不报告通过。每次截图写入独立子目录，失败证据保留。卡片切换等待本次原生打开请求及对应题干渲染完成，避免把前一卡误认成新卡。

`validate_source_course.py --bundle <编译目录> --output <全新隔离目录>` 通过真实安装器和 `create_app` 载入首 Topic，分别保存学习顺序与真实判题证据。完整顺序使用明确标注的确定性判题及注入时钟，检查各节首次指导顺序、组块/卡片所属指导已读、正常阶段的当前节约束、补学阶段和全部点完成；它不证明真实学习耗时或语言判题质量。真实判题另用独立测试学员的正常初学正误抽样及管理员单张多点卡抽样，不修改时钟，不宣称管理员卡片代表全程学习完成。两者都遵守实际提交限流，不扩成逐卡语义审查。截图后停止临时服务，保留原生源、安装报告、截图与状态记录。
# 课程主责的全局收束

分域协调的原始调用和 `combined.json` 保留不动。若同一知识出现相反移交或循环主责，使用现有生产脚本的 `--adjudicate-coordination <combined.json>`，先对全部原主张做可追溯的精确概念分组，再用完整相关 Topic 记录及其完整自然来源小节裁定。分组不选主讲，裁定不按整词或整 Topic 一刀切；普通回顾和应用不自动构成重规划理由。

原有结构化关系已经给出唯一且一致主讲、没有相反主张或独立事实疑点时，直接保留原关系和出处，不重复调用模型审核。冲突说明中的显式移交方向由同一 `accepted_stage` 有界提取，逐条绑定原 `repair_instructions` 的精确引用；未明确的细义项、复合消费者或旧单元级字段保持未决，不按标题或关键词猜主讲。`--responsibility-directions-only` 可仅完成这一可接续阶段。提取不能修复循环；原有方向一致后才可机械承接，真正竞争、歧义或循环进入完整证据裁定。

裁定把互相独立且容量允许的完整概念组件合批，不能为窗口任意拆开一个概念。`--responsibility-capacity` 接受按真实调用测得的输入比例、开销、有效窗口和输出预留参数；输出预算随本批组件和原主张处置数增长。请求仅对重复的完整 JSON 值和字段列表做可逆编码，原始文字、完整相关 Topic 和自然来源小节逐字段还原并核对哈希；编码后的实际请求与完整输入分别绑定。无法安全容纳的组件保留为明确阻塞，不截断证据。每个原主张的处置仍可回溯到原始调用。

`--responsibility-observations` 只接收绑定原始 combined 哈希的独立事实观察，不把它当批准。每个原主张均须有明确去向；真实裁定凭据、完整输入与输出保留在原协调阶段下。机械合并另存 `adjudicated.json`，核验全部真实调用、来源覆盖与全图环路后，才将一致的局部职责反馈交给原完整材料规划。已通过且输入未变的计划不因此整批重做。
