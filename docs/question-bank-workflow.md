# 问答题转换与私有题库

> 2026-10-03：用户在规则确定后要求开始执行。本轮恢复代码落实、离线验收与既定交付，新增付费 API 预算仍为 **0**。转换器已移除逐题审核、盲审和嵌套重试；预算由持久 SQLite 记录强制执行。下面的规则在本轮保持冻结。

共享题型用 `interaction.type=choice` 表示单项选择，支持 2–12 项。本次数学「数字化为字母」采用六选一、每道原题一套：第 4 模块的 Example 与全部 Practice 转填空，其余模块转选择。原始 Topic、题目 ID、标准答案、解析、Practice 队列和 FSRS 身份不变。

## 质量规则

1. 原答案和解析是来源依据，不让模型重新解题或改写正确答案。填空只机械改写设问，不调用 LLM。
2. 每道选择题恰好一个正确项和五个干扰项。脚本全量检查结构、数量、选项 ID、精确数值互异、与正确答案不等价以及来源绑定；可由题面严格推出的范围才可作硬检查。
3. 干扰项应与题目相关、具有迷惑性。只改分母、分子、系数或符号都可以；两个或多个同样合理的中心也可以。禁止的是整组选项明显围绕正确答案这个唯一中心变化，从而泄露答案。
4. 不强制三种错误机制，不硬性限制局部变形数量，不把字符相似度、统一量级倍数或“正确值为整数”等启发式规则当作跨题通用的否决标准。相关提示只供质量判断。
5. 生成项可附一句设计理由，不要求为每项编造完整错解，也不把纯数值变形说成已观测到的学生错误。不要求模型输出冗长推理。
6. “是否自然、是否太容易排除、是否形成明显中心”由 Codex 按这些标准一次性抽样判断。模型自称通过、反复审核直至通过，均不构成质量证据。抽样通过不宣称所有题目的干扰效果已经获得实证验证。

## 固定工作流

1. **先离线设计，再冻结。** 在任何付费调用前固定输入范围、题型映射、提示词、输出结构、硬检查、抽样依据、模型与思考配置、预算和停止条件。批次执行中不修改这些规则。发现规则缺陷即结束本轮，记录证据；修订属于下一轮离线设计，不能改完马上重启生产。
2. **先复用已有产物。** 保留原始请求、响应和来源哈希。来源未变、符合规则的产物离线复用；规则或文档更新不等于全部缓存作废。确有受影响题目时只处理这些题目，禁止整批重做。人工改过的候选不能冒充自动生产通过的证据。
3. **确需从零生产时，小批一次生成。** 每个请求最多四题，每题直接生成五个干扰项；不再先生成十二个候选，不再嵌套组选。首批八题覆盖五个待转换模块、不同数值形式及边界情形，计入正式题目，不额外造一套试题。
4. **先完成本地校验和小样判断。** 全量确定性校验均在本地运行；Codex 对首批八题按固定标准检查，另检查脚本标记的疑点。不调用另一份 API 逐题审核或盲审。小样不通过则停止，不进入全量生产。
5. **通过后仅生产剩余题目。** 沿用同一套提示词与标准，每题正常只生成一次。格式、数量、重复值等明确硬错误可以只重试受影响题目一次，并占用同一个总预算；不能把主观意见变成自动重试循环。
6. **达到停止条件就结束本轮。** 同一类错误在修复重试后仍出现、抽样质量未通过、规则本身存在争议、预算不足或账目不完整，均停止发起新请求，保留失败项。禁止为了凑齐数量放宽标准、改候选或继续增大重试次数。
7. **内容生产与软件验收分开。** 结构与交互优先用本地 fixture 和模拟响应验证；真实判题 API 的必要抽样也必须单列并计入本次预算，不能隐藏在浏览器验收或全量测试中。代码或 UI 重测不触发重新生成题库。

## 调用预算与记账

- **当前任务：新增付费 API 调用为 0。** 复用已产生的 80 道选择题和 16 道填空题，不因本次规则调整重新生成。网络发布和只读状态核验不属于模型生产请求；验收不调用模型。
- **若以后确需从零生产同规模的 80 道选择题：** 按每请求四题计划 20 次生成请求；包括小样、补充、传输重试与任何真实 API 验收在内，整轮最多 24 次 HTTP 请求、输入加输出合计最多 250,000 token。最多两个并发，单请求输出上限 8,192 token，思考 token 必须包含在该上限中。这些是安全上限，不是应当用满的配额，也不是对通过率的保证。
- 模型、思考配置与单次限制在运行前固定；不在执行中临时升档、增加思考量、提高并发或扩大预算。如果既定配置无法在限额内产出，停止并说明，不默认申请更多调用。
- 总计数覆盖所有阶段、进程、重启和重试。发请求前先预留一次调用、输入的保守上界及最大输出预算；余额不足不得发送。已经发出但没有完整响应的请求也记一次，并保守占用 token 预留，不能按零成本处理或自动重发。
- 运行前按当时官方价格、全部输入未命中缓存的保守情况列出金额上界。无法确定价格、输出限制的实际覆盖范围或剩余额度时不启动。费用上限不能只靠事后统计。
- 按供应商响应 ID 去重保存模型、阶段、输入 token、输出 token、思考 token、缓存命中与错误；缓存读取单独记录，不充作新网络调用。每个小批结束展示累计量和剩余预算。
- 停止请求优先于补齐产物：取消尚未发出的任务，不为收尾补调用；在途请求立即停止本地消费并记为费用可能尚未结算，不能声称本地取消必然免计费。

预算实现位于 `conversion_budget.py`，在调用前预留额度，交易同时约束请求数、token、人民币费用与在途数量。未完成账目的请求不能在重启后自动释放或重发。账本中的方案与限额不可在续跑时改写。实际生产顺序执行，最大在途限制仍覆盖并发启动的进程。

## 入口

已有完整 `bank.json` 时，普通入口和 `--verify-only` 都只复核并复用，不创建模型客户端：

```powershell
& D:/AppData/GraspMemoEdu/venv/Scripts/python.exe -m graspmemoedu.question_conversion `
  --course '<原题JSON>' --output '<已有私密产物目录>' --verify-only
```

缺少完整题库时，默认预算为零，发请求前即停止。未来确需付费生产，须以 `--budget <JSON>` 提供 `conversion_budget.DEFAULT_LIMITS` 的全部字段；不得超出本文上限。价格按官方每百万 token 的人民币价填写，并填 `pricing_checked_on`、官方 `price_source`、`max_cost_rmb`；报价超过一天不得启动新请求。`model` 固定为 `deepseek-flash`，`thinking` 在建账时冻结，高思考模式也显式传送 `max_tokens`。

新批次先生成八题后返回 `sample_review_required`。Codex 阅读 `sample.json` 并完成既定质量抽样后，才使用 `--sample-reviewed` 继续余下题目；该开关记录执行者完成质量检查，不要求用户二次批准。已生成内容不重发。原 `--workers`、`--attempts` 和逐题审核入口已删除。

输出限制依据：[DeepSeek Chat Completions 参数](https://api-docs.deepseek.com/api/create-chat-completion/)。生产请求只生成内容，本地测试使用模拟响应，响应中的输入、输出与思考 token 分别留档。

## 数据与既有实现

所有原题、API 请求/响应、生成题库留在 D 盘产物目录或服务器私密数据目录，不提交源码仓库或 Pages。公开前端只拿已呈现题目的选项，不拿答案键。内容生产只使用 `GRASPMEMOEDU_IMPORT_API_KEY`，不使用 Codex 通用外包密钥或网站判题密钥、配额；配置读取规则见作者导入文档。

转换器目前仅支持无图片依赖的数值型综合范式 Topic。第 4 模块保留题干并追加结果空，沿用原数学语义判题，不收窄等价表达式的接受范围。编译复用现有安全 Markdown/MathJax 流程；新小样不输出可安装题库，安装器也继续拒绝旧版 `pilot` 题库。`--verify-only` 只作本地回读。

旧版 `numeric-six-choice-10` 的历史通过记录只证明按当时流程生成完成，不等于本次规则已经落地，也不等于已经部署。干扰项实际区分度仍需以后用学生作答数据判断。

## 发布、历史与恢复

先备份正式站点，再经 SSH 将已验收的私有 `bank.json` 交给 `python -m graspmemoedu.question_bank --course <正式TopicJSON> --bank <题库JSON> --data-dir /var/lib/graspmemoedu`。无网页安装或改题接口。

题库保存在 `question-banks/<topic_id>/<sha256>.json`，`active.json` 原子切换当前版本。已存版本不覆盖、不删除。原课程 JSON 及其 version 不修改，也不为转换重置或迁移学习记录。

每个新 Lesson 步骤固定题库版本；每个新 Review 轮次固定版本。历史步骤/轮次没有该字段时永远读取原题，即使后来安装了题库。新题型的失败重试、历史回答和文字纠错均使用当时固定的版本。缺失或哈希不匹配的版本报错，不偷偷回退到另一道题。只切换 active 指针可以影响后续呈现，不能改写已呈现题目。

格式 2 的整站备份包含所有题库历史文件及当前指针。备份和恢复验证路径、源题哈希、文件内容哈希及数据库引用，旧版没有题库的备份仍可恢复。验证使用 `tests/test_question_bank.py`、备份测试及 `question_bank_fixture.py` / `question_bank_acceptance.mjs` 的隔离真实 Chrome 流程；测试内容不能发布正式课程。
