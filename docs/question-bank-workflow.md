## 质量规则

1. 原答案和解析是来源依据，不让模型重新解题或改写正确答案。填空只机械改写设问，不调用 LLM。
2. 每道选择题恰好一个正确项。数学既有题库保持六项；物理经用户确认采用 2–6 项：完整的单一能否判断用两项，两个独立判断用四种组合，其他自然语言合答用四项，纯公式和标量计算用六项。脚本全量检查结构、数量、选项 ID、精确数值互异、与正确答案不等价以及来源绑定；可由题面严格推出的范围才可作硬检查。
3. 干扰项应与题目相关、具有迷惑性。只改分母、分子、系数或符号都可以；两个或多个同样合理的中心也可以。禁止的是整组选项明显围绕正确答案这个唯一中心变化，从而泄露答案。
4. 不强制三种错误机制，不硬性限制局部变形数量，不把字符相似度、统一量级倍数或“正确值为整数”等启发式规则当作跨题通用的否决标准。相关提示只供质量判断。
5. 生成项可附一句设计理由，不要求为每项编造完整错解，也不把纯数值变形说成已观测到的学生错误。不要求模型输出冗长推理。
6. “是否自然、是否太容易排除、是否形成明显中心”由 Codex 按这些标准一次性抽样判断。模型自称通过、反复审核直至通过，均不构成质量证据。抽样通过不宣称所有题目的干扰效果已经获得实证验证。

## 固定工作流

1. **先离线设计，再冻结。** 在任何付费调用前固定输入范围、题型映射、机械组、提示词、输出结构、硬检查、抽样依据、模型与思考配置和停止条件。设计时大致掌握调用规模即可，不做预算核验。批次执行中不修改这些规则。发现规则缺陷即结束本轮，记录证据；修订属于下一轮离线设计，不能改完马上重启生产。
2. **先复用已有产物。** 保留原始请求、响应和来源哈希。来源未变、符合规则的产物离线复用；规则或文档更新不等于全部缓存作废。确有受影响题目时只处理这些题目，禁止整批重做。人工改过的候选不能冒充自动生产通过的证据。
3. **先合并机械变体，再小批一次生成。** 每个请求最多四道代表题，按固定选项数直接生成所需的干扰项或可复用模板；不生成候选池。题干、答案、约束和附图说明仅有数值替换、其他结构一致的题可组成机械组；条件或设问变化则分开。模型只处理代表题，脚本用原题参数精确展开其余题。首批八道代表题覆盖 Topic、答案形态及机械组，计入正式题目。
4. **先完成本地校验和小样判断。** 全量确定性校验均在本地运行；Codex 对首批八题按固定标准检查，另检查脚本标记的疑点。不调用另一份 API 逐题审核或盲审。小样不通过则停止，不进入全量生产。
5. **通过后仅生产剩余代表题。** 沿用同一套提示词与标准，每组正常只生成一次。所有机械展开结果均检查选项数量、互异及与原答案不等价。格式、数量、重复值等明确硬错误只重试受影响代表题一次；不能把主观意见变成自动重试循环。
6. **达到停止条件就结束本轮。** 同一类硬错误在修复重试后仍出现、抽样质量未通过、规则本身存在争议或请求结果不确定，均停止发起新请求，保留失败项。禁止为了凑齐数量放宽标准、改候选或继续增大重试次数。
7. **内容生产与软件验收分开。** 结构与交互使用本地 fixture 和模拟响应验证；真实判题 API 的必要抽样须明确列出，不能隐藏在浏览器验收或全量测试中。代码或 UI 重测不触发重新生成题库。

## 调用规模与记录

预算只在设计时按代表题数量粗估，不查询余额，不配置金额审批、token 总额度或请求总数门禁。通过机械组复用、每请求最多四道代表题、每组一次生成、无付费审核/盲审来控制规模。

默认采用 `deepseek-flash` 非思考模式，顺序调用，单请求 `max_tokens=8192`。概念性干扰项修复批次显式固定 `thinking=true`、`reasoning_effort=low`、`max_output_tokens=16384`，每批两道代表题；已有合格结果不重跑。[官方思考模式文档](https://api-docs.deepseek.com/guides/thinking_mode/)列明默认思考强度为 high，不能依赖默认值而耗尽输出空间。模型与输出配置在运行前固定，不在生成过程中加档或反复调整。`conversion_run.py` 只保存冻结方案、请求去重、响应与用量记录；不做财务核验。请求超时或结果不明时停下，避免自动重发造成重复生产。旧 `conversion_budget.py` 仅保留历史实现及回归证据，当前转换入口不再调用其预算门禁。

## 入口

已有完整 `bank.json` 时，普通入口和 `--verify-only` 都只复核并复用，不创建模型客户端：

```powershell
& D:/AppData/GraspMemoEdu/venv/Scripts/python.exe -m graspmemoedu.question_conversion `
  --course '<原题JSON>' --output '<已有私密产物目录>' --verify-only
```

数值转换器可用 `--config <JSON>` 固定 `model`、`thinking`、`max_output_tokens` 和可选的 `reasoning_effort`，不再提供 `--budget`。显式执行生产入口才创建模型客户端。

新批次先生成八题后返回 `sample_review_required`。Codex 阅读 `sample.json` 并完成既定质量抽样后，才使用 `--sample-reviewed` 继续余下题目；该开关记录执行者完成质量检查，不要求用户二次批准。已生成内容不重发。原 `--workers`、`--attempts` 和逐题审核入口已删除。

输出限制依据：[DeepSeek Chat Completions 参数](https://api-docs.deepseek.com/api/create-chat-completion/)。生产请求只生成内容，本地测试使用模拟响应，响应中的输入、输出与思考 token 分别留档。

## 数据与既有实现

所有原题、API 请求/响应、生成题库留在 D 盘产物目录或服务器私密数据目录，不提交源码仓库或 Pages。公开前端只拿已呈现题目的选项，不拿答案键。内容生产只使用 `GRASPMEMOEDU_IMPORT_API_KEY`，不使用 Codex 通用外包密钥或网站判题密钥、配额；配置读取规则见作者导入文档。

数学 `question_conversion.py` 继续保留原数值规则；数学第 4 模块沿用语义判题，不改变已发布题库。

物理入口为 `python -m graspmemoedu.physics_question_conversion --courses <按顺序的Topic JSON列表> --output <私密目录>`。`--plan-only` 只做题型映射和机械分组；默认先生成八道代表题小样，完成 Codex 检查后用 `--sample-reviewed` 继续；`--verify-only` 只回读已编译题库。可选本地作者依赖见 `requirements-conversion.txt`，学习服务器不需要这些依赖。

物理中，完整答案是一个带原单位的整数物理量（或纯整数）时，保留物理量名、等号和单位，只挖空整数，采用脚本精确判题。分数、根式、关系式、判断和多问合答均转选择题；不从完整答案里随意挑一个整数、不更换单位来制造整数。公式局部数字和 `x=0` 这类坐标关系不能按整数计算题处理。

机械模板仅允许具名参数与受限算术 AST，不执行模型代码。整个算术写在一个 `[[表达式]]` 内，拒绝 `2[[p1]]` 等会拼接数字的形式。每个变体绑定自己的原答案、参数和原附图；模板展开后统一精确化简数值、约分并渲染，逐项检查重复及可解析的代数等价。自然语言语义不冒充为脚本全量证明，由固定小样检查其设计质量。

新生产输出将 `value` 拆为固定文本与 `{"expr":"算术表达式"}` 的 JSON 数组，脚本负责拼接和数学排版，从生成接口移除字符占位符；旧模板只在复用时继续支持。`parameter_roles` 标出每个参数在题面或答案中的来源，避免把答案分母误认为题面物理量。局部修复请求携带原失败候选、具体选项序号、展开参数、展开值及等价碰撞对象。同批中合格题立即缓存，不因另一题失败而丢弃。恢复工具回读原始请求和响应、绑定未变的源题及参数组；只有通过硬检查和质量检查的候选才可复用，且回读校验候选未被人工修改。

返回 JSON 部分破损时，只提取原响应中可独立解码的完整题目对象；不补写或修正对象内部内容。缺失题、重复 ID 和不完整对象进入原有一次局部修复，完整合格题保留。字符串里的 JSON 不作为独立题目读取。

长响应可在冻结配置中指定 `stream=true`，按官方 SSE 协议接收增量并合并成同一份响应；只有收到终止标记和完成状态才进入校验，同时记录服务端用量。中断流仍标记结果不确定并结束本轮，不自动重发。2026-10-04 的断连请求保留为不确定记录，恢复批次只复用已收到且验证通过的内容。

有限判断组合直接依据来源答案枚举，不调用模型；单一能否题只呈现完整的能/不能选项，完整推导仍保留在原参考答案和解析中。生成的合答选项必须内部一致，不能复制正确推导再反转一句结论，也不能仅靠改单位或附加未被问到的理由凑项。首轮物理小样因这些问题停止；用户确定 2–6 项后才启动新方案，旧响应保留，已确认合格的候选可通过 `--reuse-reviewed` 绑定原始来源复用，不人工改写候选。

代表题的原始图片通过多模态输入提供，不能只传文件名或图注。编译保留原 HTML（含内嵌图）逐字节前缀，只用现有安全 Markdown/MathJax 渲染追加提示与选项。新小样不输出可安装题库，安装器继续拒绝 `pilot` 题库。

## 发布、历史与恢复

先备份正式站点，再经 SSH 将已验收的私有 `bank.json` 交给 `python -m graspmemoedu.question_bank --course <正式TopicJSON> --bank <题库JSON> --data-dir /var/lib/graspmemoedu`。无网页安装或改题接口。

题库保存在 `question-banks/<topic_id>/<sha256>.json`，`active.json` 原子切换当前版本。已存版本不覆盖、不删除。原课程 JSON 及其 version 不修改，也不为转换重置或迁移学习记录。

每个新 Lesson 步骤固定题库版本；每个新 Review 轮次固定版本。历史步骤/轮次没有该字段时永远读取原题，即使后来安装了题库。新题型的失败重试、历史回答和文字纠错均使用当时固定的版本。缺失或哈希不匹配的版本报错，不偷偷回退到另一道题。只切换 active 指针可以影响后续呈现，不能改写已呈现题目。

格式 2 的整站备份包含所有题库历史文件及当前指针。备份和恢复验证路径、源题哈希、文件内容哈希及数据库引用，旧版没有题库的备份仍可恢复。验证使用 `tests/test_question_bank.py`、备份测试及 `question_bank_fixture.py` / `question_bank_acceptance.mjs` 的隔离真实 Chrome 流程；测试内容不能发布正式课程。
